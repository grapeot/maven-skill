# Maven General 消息草稿与定点操作

本参考面向 AI Agent，提供 General 频道草稿填写、链接核验及已发消息定点操作规范。基于 2026-10 的可见浏览器实测；DOM 可能变化，每次操作前核对现场。本参考不新增 CLI 或后端 API，也不授予任何线上操作权限。

## 1. 授权边界与只读契约

现有 Maven CLI 业务命令保持只读，尤其 `lessons` 与 `promo-codes` 不得增加写操作。按 [session.md](session.md) 核验已登录的可见 Chrome 会话后，只有用户明确授权 General 草稿填写，才可填入指定内容。

填草稿必须止步于编辑器，严禁点击 `Send` 或按 `Enter` 提交。填草稿授权不隐含发布、编辑已发消息或删除权限；已发布状态的变更需针对具体消息、具体动作单独授权。

## 2. Cohort 选择与频道导航

导航默认使用可见窗口中的独立工作标签页，不覆盖用户现有页面。若用户已在指定页面准备草稿，先核对该页实时状态与授权，不能另开页重复填写；已填草稿的工作页按第 9 节保留，不套用只读任务结束即关页的清理规则。

1. **判定目标 Cohort**：结合目标活动日期、页面显示时区及 `in_session` 状态筛选期次，不能盲选 `latest`；它可能指向 upcoming 下一期。列表字段与选期规则见 [courses_cohorts.md](courses_cohorts.md)。
2. **进入学生端视图**：在目标 cohort admin 页面读取真实的 `View student home` 链接并进入。
3. **定位 General**：从实际 DOM 读取 General 频道链接，不按经验猜测或拼接 URL。
4. **等待 SPA 就绪**：点击后以目标 URL 或目标 DOM 出现作为等待条件；立即读取的 URL 可能仍是旧值，固定 `sleep` 也不能证明导航完成。

## 3. 每次写入前重读实时状态

浏览器由人机共用，用户可能在 Agent 处理中人工编辑或发送。每次下一步写入前都要重新读取 live state，不能沿用上一轮快照。

已有用户草稿不得覆盖。若出现预期外变化，停止写入并核对。空框也不等于丢稿：用户可能已改写正文并手动发送。先核对相关已发消息与用户动作，再决定后续操作，不能盲目重复粘贴。

## 4. Quill 编辑器填写

已验证输入框为 `.ql-editor[contenteditable=true]`，其父节点 `parentElement.__quill` 挂载 Quill 实例。实测合成 `ClipboardEvent` 的 `paste` 没有生效；通过父节点实例调用 `dangerouslyPasteHTML` 能填入内容并触发编辑状态。

1. **紧邻写入确认唯一空目标**：确认只有一个可见目标编辑器，且没有已有文字、链接或嵌入对象。不能只靠 `innerText.trim()` 判空；也不能把 Quill 空编辑器自带的空段落误判为用户草稿。无法确认空状态或父节点实例时停止，不猜另一个编辑器。
2. **先校验 HTML 和链接**：只传入已核对的授权内容，完成下一节的链接检查后才执行。方法名含 `dangerously`，不得接入任意未经核对的 HTML。
3. **定点调用**：以下仅说明已验证的调用表达式，`editor` 是刚确认的唯一目标，`authorizedHtml` 是已校验的授权稿：

   ```js
   editor.parentElement.__quill.clipboard.dangerouslyPasteHTML(authorizedHtml, 'user');
   ```

调用后立即读回核验，不把无报错当作成功，也不由此新增通用自动写入 CLI。

## 5. 占位链接必须挡在可发送编辑器之外

写入前遍历 HTML 中全部 `href`。`{{RECORDING_URL}}` 等未替换占位符不能作为真实地址进入编辑器：实测 Quill 会补成 `https://{{RECORDING_URL}}`，发布后又成为 `https://%7B%7BRECORDING_URL%7D%7D`，看似可点但实际无效。

同时检查原始地址与 URL 解码后的地址是否残留 `{{`、`}}` 或其他占位标记；解码失败也不能跳过核验。仅有合法 `https:` scheme 不足以证明地址有效。逐条确认地址就是授权稿中的真实目标，而非待替换模板。

未取得真实链接时，完整草稿留在本地；或者经用户确认，剔除缺失链接对应的内容后再填。不能以可点击的假地址交付。若以后获准发布，发布前仍须检查链接；本参考不授予发布权限。

## 6. 写入后核对正文、全部链接与排版

从目标编辑器读回 `innerText`，与原稿规范化空白后比较，同时检查段落、列表、强调等排版。规范化空白只用于比较，不能掩盖文字遗漏或排版丢失。

提取全部 `a[href]`，逐条核对显示文本、实际 `href` 和链接总数。例如真实目标的公开示例可写成 `https://example.com/recordings/session-01`。一次实操核对了 16 条链接；这是单次稿件规模，不是平台限制或通用预期数量。

## 7. 按用户已发措辞重填

用户要求按本人已发消息重填、仅换指定链接时，先读取其可见目标消息，保留用户全部其他措辞与排版。

1. **保存私有基准**：将目标消息正文 HTML、plain text 和 link map 存到私有 session 输出目录（如 `.local/`，目录 `0700`、文件 `0600`）。公开文件不得包含真实用户话语、姓名、频道 ID 或业务链接。
2. **单点替换**：以这份已发正文为唯一基准，仅替换用户指定的目标 URL，其余不变。先确认目标地址及出现位置唯一、符合授权；有歧义先核对，不能扩大替换范围。
3. **重新验收**：按第 6 节比对正文、排版和全部链接，不退回 Agent 早先的旧稿。读取已发内容不构成修改或删除该消息的授权。

## 8. 已发消息定点编辑与删除

以下仅适用于已获得具体动作授权的任务。仅填草稿的任务不得执行这些操作。

1. **正文唯一定位容器**：用目标消息独有正文定位节点，通过 `.closest(...)` 找到它所属的实际 message group。容器选择器按现场 DOM 确认，不虚构固定 selector。只在该 group 内找 `Edit` 或 `Delete`，禁止点页面第一个 `Delete`；无法唯一定位时停止。
2. **删除前备份与授权核对**：将目标消息完整备份到私有目录，确认已有对该消息的明确删除授权；已有明确授权时不机械重复询问。
3. **原生确认框陷阱**：Maven Delete 触发 JS `confirm`，实测文本为 `Are you sure you want to delete this message?`。Playwright 无 dialog listener 时默认 dismiss，所以 `click` 无报错不代表删除成功。
4. **仅处理本次确认**：获删授权后，在点击前安装仅匹配 `type === 'confirm'` 和上述完整文本的 dialog handler，再点击已定位的 Delete。仅该确认可 `accept`；其他 dialog 不自动接受，出现异常则停止核对。监听器限本次动作并在结束后卸载，不使用自动接受全部 dialog 的脚本。
5. **权威视图验收**：编辑后读回目标正文与链接；删除后 reload 或读取权威视图，确认目标确实不存在。若存在未发草稿，先保护并备份，不能直接刷新丢失草稿。不得因目标暂时未渲染或点击未报错就宣称成功，也不得盲目重复删除。

## 9. 保留草稿现场，区分完成状态

草稿核验后调用 `bring_to_front`，停留该页、保留窗口供用户检视，不刷新、不关闭。草稿的服务端持久化（draft durability）未经验证。

汇报必须区分**当前编辑器已填**、**已发布**与**服务端持久化**。第一项不能证明后两项；不要为验证草稿持久化而擅自刷新或发送。

## 10. 验收清单

- [ ] 按活动日期、时区与 `in_session` 核对 cohort，经真实页面链接进入 General。
- [ ] 每次写前重读 live state，确认唯一空编辑器，保护已有草稿且未重复粘贴已发送内容。
- [ ] 原始及 URL 解码后的全部 `href` 无占位地址，内容符合具体授权。
- [ ] 写后比对 `innerText`、排版及全部链接的文本、地址与数量。
- [ ] 按用户措辞重填时，私有保存 HTML、plain text、link map，仅替换指定 URL。
- [ ] 草稿任务未点击 Send、未按 Enter 提交；窗口置顶保留，未声称服务端持久化。
- [ ] 如获准操作已发消息，目标唯一、授权对应；删除前备份、精确处理确认框并以权威视图验收。
