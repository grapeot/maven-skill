# Maven 新建班期（Cohort Creation）操作参考

本文面向具备 Playwright / CDP 浏览器操作能力的 AI Agent，定义为既有课程新建班期的目标、授权边界、页面实测观察与验收标准。基于 2026-10 的可见浏览器实测；按钮和字段可能变化，操作前核对现场 DOM。

## 1. 目标与能力边界

- **CLI 只读与浏览器写操作分离**
  - `maven-skill` CLI 不包含新建班期的专用子命令；会话管理和只读业务命令见根 skill。
  - 新建操作复用已登录持久 Chrome 会话中的独立工作标签页，通过 CDP / Playwright 操作页面真实 DOM，不调用或逆向 Maven 私有 API。
- **动态路由发现与公开文件脱敏**
  - 目标课程管理页 URL 通过 `maven-skill courses list` 动态获取，不在公开文档或脚本中写入客户课程名、真实 slug、实际班期日期、课程模块名或本机路径。
- **可见会话与认证核验**
  - 按 [session.md](session.md) 建立会话；用户明确要求打开窗口时可执行 `maven-skill session open`。
  - 业务操作前先通过 `session status` 确认 `browser_connected: true`，再通过业务命令核验登录态；未认证时交由用户人工登录。默认保持可见窗口，headless 仅在明确授权后使用。

## 2. 授权与操作范围

- 新建班期须具备用户对目标课程与起止日期的明确授权，并从会话上下文确定完整年份。用户已明确要求新建时即构成授权，不再重复确认；仅讨论排期时不创建。
- 严格区分**创建草稿**、**发布/开放报名**、**发送通知或修改商业设置**。
- 新建请求默认止步于已核验的草稿。本参考未对发布动作做自动化实测；用户自行发布或改动活动，不属于 Agent 已验证的自动化流程。
- 若用户明确要求开放报名，按现场 UI 核验执行，不凭本参考推断发布步骤。未获具体指令，不顺手修改报名截止时间、课程价格、公开落地页或发送邮件。

## 3. 前置核查与复制源选择

- **排重与完整度检查**：运行 `maven-skill cohorts list --course <COURSE_ADMIN_URL>`，检查 `completeness` 并核对是否已有目标班期。列表不完整时先从页面补足排重依据，不能据部分结果断言不存在。
- **复制源甄别**：最新班期可能仍为草稿（CLI 将其归为 `upcoming`），不要盲选 `latest` 作为复制源，也不按 slug 数字猜测顺序。选择用户指定或经核实材料最新的源，读取其 `Overview`、`Settings` 与 `Syllabus`，核对日期、起止钟点、时区及模块材料。
- **日期跨度**：日期差 14 天与包含首尾共 15 个日历日是同一跨度的不同表述。以用户确定的完整年份起止日期为准，不因口头说两周零一天就再加一天。历史班期的星期安排不是平台规则。

## 4. 创建弹窗交互与受控输入实测观察

在课程管理页 `Cohorts` 区点击 `New cohort`，打开 `Create a new cohort` 弹窗：

1. **教学方式**：选项包含 `Live`（固定日期）与 `Self-paced`。本参考实测的是 `Live` 新建路径。
2. **复制源**：`Copy course materials from existing cohort` 为原生 `<select>`，列出既有班期及 `Start from scratch`。`<option>` 的 `value` 是内部 ID，不等于 cohort slug；用实际 label/value 配对，验证唯一性后选中。
3. **复制与导入的区别**：用户同意沿用旧材料时，在该创建弹窗中选已核实的源。不要改用 `Syllabus` 页的 `Import content`：后者会替换已有 syllabus 并删除学生记录，不能用于追加内容或补救创建失败。新建不带材料的班期则选 `Start from scratch`。
4. **起止输入**：`Starts` / `Ends` 均为 text input，观察格式为 `MM/DD/YYYY h:mm AM/PM`。实测初始日期跨度为三周、钟点均为 `12:00 PM`；这是一次观察，不是默认值契约，须按目标填写。
5. **钟点落盘陷阱**：常规 `fill` 加 `Tab` 可写入日期，但 DOM `value` 不证明已持久保存。实测一次输入 `9:00 AM`，创建后 `Settings` 实际仍为 `12:00 PM`。不要猜测内部原因；任务要求准确钟点时，须在创建后刷新读回，发现不一致则按授权经实际 UI 修正并再次验证。未指定钟点时也应汇报实际值，不假装与源班期完全一致。

## 5. 单次提交与防重复创建

- 核对弹窗各项输入后，仅点击一次 `Create cohort`，按钮会变为 `Creating…`。
- 实测点击两秒后仍在创建，随后才完成跳转。页面未完成跳转不代表创建失败，不要再次提交或重跑创建流程。
- 先通过新的只读 `cohorts list` 或刷新权威管理页，检查是否已经创建成功。无法确定时保留待确认状态并汇报，不重试创建。
- 创建后的管理页路径为 `<COURSE_ADMIN_URL>/cohorts/<slug>`；以页面实际链接为准，不猜新 slug。

## 6. 创建后状态、顺延内容与 Settings 核验

- **草稿与 CLI 状态区分**
  - 实测初始状态为 `Draft`、报名 `Closed`，概览页提供 `Review and open enrollment`。
  - CLI `cohorts list` 同样把草稿归为 `status: upcoming`。`upcoming` 不等于已开放报名，必须以页面权威状态为准。
- **模块、顺延活动与作业截止日**
  - 选源创建时实测复制了模块与 live events。在 `Overview` 核对模块及活动数，在 `Syllabus` 核对章节与 bonus 内容；数量相同不代表内容已逐项验证。
  - 活动日期会随新班期顺延，复制的作业与反思 due date 也会展示。逐项核对活动名称、日期、时刻、时区、optional 标记及是否落在课程范围内，并检查作业 due date。
  - 自动顺延不等于用户确认或无节假日冲突，也不保证所有排期均正确。汇报待确认项；用户后来已手动修改的活动，不得默认覆盖回顺延值。
- **Settings 衍生日期读回**
  - 读取 `Cohort start date`、`Cohort end date`、`Payment deadline`、`Student portal open date` 及页面显示时区。这些时间以页面所示本地时区表示，例如 `America/Los_Angeles`，不可固定假设为 UTC 或浏览器外的其他时区。
  - 实测创建后付款截止为开课前一天中午、portal 开放为前两天中午；仅为单次观察，每次必须读回，不把它们写死为自动配置规则。

## 7. 验收与交付

完成后重新加载权威 `Overview`、`Settings` 页面，并结合只读 `cohorts list` 验证：

1. 目标课程下仅生成一个符合目标的新 cohort；记录实际管理链接与 slug。
2. 起止日期、实际钟点、显示时区，以及付款截止与 portal 开放日期已读回；日期与授权目标一致，指定钟点也须一致。
3. 按所选复制源核对材料；若选 `Start from scratch`，验证未意外复制材料。逐项检查活动与作业排期，区分已核验内容、待确认项和未检查的部分。
4. 如实汇报当前草稿或报名状态，不把 CLI `upcoming` 当作开放报名；只有获授权且实际完成发布验证后才能报告已发布。
5. 客户操作证据只存本地 `.local/`，不进入公开 Git，避免采集无关学生 PII。向用户交付课程/班期管理链接、完整日期与时区、材料复制情况、当前报名状态及排期待核项。
